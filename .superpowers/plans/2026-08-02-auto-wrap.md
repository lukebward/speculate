# Auto-wrap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Newly added MCP servers get wrapped automatically, via a user-scope Claude Code plugin whose single `SessionStart` hook runs a new `speculate sync`.

**Architecture:** Extract `speculateOn`'s wrap loop into one shared function so `on` and `sync` cannot drift; add `sync` as a fast, silent, unattended command guarded by a per-project config hash, a lock, and a hard timeout; ship a hook-only plugin installed at user scope by `on`.

**Tech Stack:** TypeScript (strict), Node >= 18, vitest, no new dependencies.

**Spec:** `.superpowers/specs/2026-08-02-auto-wrap-design.md` (read it; it records the measured one-session lag and why the design accepts it).

## Global Constraints

- Branch `auto-wrap`, already created off `focus-mcp`. Do not merge or push.
- Plugin id is exactly `speculate-autowrap`. The retired `≤0.10` ids are `speculate` and `speculate@speculate`; auto-wrap must never match legacy cleanup.
- `sync` inherits every consent gate unchanged: unapproved `.mcp.json` servers skipped, `isWrappedEntry` skipped, non-stdio passed through, names starting with `-` skipped.
- `sync` is fail-open and silent: any error exits 0 with no output. It must never block or slow a session start.
- Hard cap on a whole `sync` run: 5000 ms. Expiry is success (exit 0).
- The hook command is an absolute `node <abs>/dist/src/cli.js sync`, never a bare `speculate` (Claude Code rejects `.cmd` shims in exec-form hooks on Windows).
- Windows is a first-class target: `fileURLToPath`, no POSIX assumptions, no shell.
- Every task ends `npx tsc --noEmit` clean and the named tests passing; Task 6 ends with the full suite green (`npx vitest run`, baseline 424 passed / 7 skipped).

- [ ] **Step 3: Implement** with `node:crypto`, sorting names so key order cannot matter:

```ts
export function effectiveServerHash(view: ClaudeConfigView): string {
  const parts: string[] = [];
  for (const [name, scoped] of [...effectiveServers(view.servers)].sort((a, b) =>
    a[0] < b[0] ? -1 : a[0] > b[0] ? 1 : 0,
  )) {
    parts.push(`${scoped.scope}${name}${canonicalJson(scoped.entry)}`);
  }
  return createHash('sha256').update(parts.join('\n')).digest('hex');
}
```

`canonicalJson` is REQUIRED: entries arrive from JSON.parse of the host config, which preserves source key order, so a plain JSON.stringify makes an unchanged server hash differently after `claude mcp add-json` rewrites the file. Sort object keys recursively; never reorder arrays (`args` order is meaningful). Tests must cover: same content different field order hashes EQUAL; nested `env` order irrelevant; reversing `args` DOES change the hash; same name at user vs local scope hashes differently.

Add `syncHashes?: Record<string, string>` to `ManagedState` and leave `loadManagedState` tolerant (an older file simply has no `syncHashes`).

- [ ] **Step 3: Implement `src/sync.ts`.** Order matters: opt-out check, then hash check, then lock, then wrap. Everything inside one try/catch that swallows and returns 0.

```ts
export async function speculateSync(opts: SyncOptions): Promise<number> {
  // `makeCtx` defaults `log` to a stderr write, and `wrapEffectiveServers`
  // logs one line per server. A session-start hook must not spray that into
  // the user's terminal, so the ctx logger is silenced and `sync` emits only
  // its own one-line summary through `report`.
  const report = opts.log ?? ((line: string) => process.stderr.write(`${line}\n`));
  try {
    const ctx = makeCtx({ ...opts, log: () => {} });
    const state = loadManagedState(ctx.statePath);
    if (state.syncOptOut?.[ctx.cwd]) return 0;
    const view = readClaudeServers({ home: ctx.home, cwd: ctx.cwd });
    const hash = effectiveServerHash(view);
    if (state.syncHashes?.[ctx.cwd] === hash) return 0; // fast path: no subprocess
    const release = acquireLock(opts.lockPath ?? defaultLockPath(ctx));
    if (!release) return 0; // another session is syncing; next session picks it up
    try {
      const record = state.projects[ctx.cwd] ?? { entries: [], updatedAt: Date.now() };
      const managed = new Map(record.entries.map((e) => [managedKey(e.scope, e.name), e]));
      const wrapped: string[] = [];
      const { failed } = await wrapEffectiveServers(ctx, view, managed, {
        mode: opts.mode ?? undefined,
        onWrapped: (name) => wrapped.push(name),
      });
      state.projects[ctx.cwd] = { entries: [...managed.values()], updatedAt: Date.now() };
      state.syncHashes = { ...(state.syncHashes ?? {}), [ctx.cwd]: effectiveServerHash(
        readClaudeServers({ home: ctx.home, cwd: ctx.cwd }),
      ) };
      saveManagedState(ctx.statePath, state);

IMPORTANT: store the hash ONLY when `failed === 0`. Storing it after a failed
wrap makes the fast path report "nothing changed" on every later session, so the
server that failed is never retried until the effective set changes again. The
same rule applies on timeout expiry: do not store.

      if (wrapped.length > 0 && failed === 0) {
        report(
          `[speculate] wrapped ${wrapped.length} new server${wrapped.length > 1 ? 's' : ''} ` +
            `(${wrapped.join(', ')}); speculation active next session`,
        );
      }
    } finally {
      release();
    }
    return 0;
  } catch {
    return 0; // fail-open: never block a session start
  }
}
```

Add an optional `onWrapped?: (name: string) => void` callback to `wrapEffectiveServers`'s opts (called on each successful wrap) so `sync` can name the servers without re-deriving them; `on` passes nothing. `wrapEffectiveServers` logs through `ctx.log`, so `sync` must construct its `ctx` with a no-op logger and emit only its own summary line.

Implement the lock in the same file:

```ts
const LOCK_STALE_MS = 30_000;
function acquireLock(path: string): (() => void) | null {
  try {
    mkdirSync(dirname(path), { recursive: true });
    try {
      writeFileSync(path, String(process.pid), { flag: 'wx' });
    } catch {
      const age = Date.now() - statSync(path).mtimeMs;
      if (age < LOCK_STALE_MS) return null; // a live session holds it
      writeFileSync(path, String(process.pid)); // stale: take it over
    }
    return () => { try { unlinkSync(path); } catch { /* already gone */ } };
  } catch {
    return null;
  }
}
```

- [ ] **Step 4: Wire the CLI.** Add `'sync'` to the `Args['command']` union and to `REST_COMMANDS`, and dispatch to `speculateSync({ self: selfCommand(), ... })`.

**DO NOT use a hard `process.exit` timer as the cap.** It can fire between the wrap loop's `mcp remove` and `mcp add-json`, deleting a server from the user's config with no restore and skipping `saveManagedState` for everything already wrapped. Reachable on a first run with a handful of servers on Windows (two `claude` spawns each). Instead use a **cooperative deadline**: check a monotonic deadline at the top of each iteration in `wrapEffectiveServers`, return the partial outcome, and let `sync` save state normally. A partial pass must NOT store the hash. Keep a hard `process.exit` only as a genuine last resort at a much higher value (60s). Also wrap `selfCommand()` in try/catch so a half-removed install cannot print a fatal on every session start.

Add one line to the MAIN command list in `HELP` (near `status`), NOT under `compatibility:` which is for the deprecated exec shim:
`  speculate sync                           wrap MCP servers added since the last run (run by the auto-wrap hook)`

`plugin/hooks/autowrap.mjs` — the orphan guard. `claude plugin install` copies the
plugin into the user's plugin directory, so it outlives an `npm uninstall` of
Speculate. Invoking the CLI path directly would then fail on every session start
forever. This wrapper checks first and exits 0 silently when the CLI is gone.
`SPECULATE_CLI` is baked in at install time.

```js
// Auto-wrap hook: run `speculate sync`, but never fail a session start.
import { existsSync } from 'node:fs';

const cli = process.env.SPECULATE_CLI ?? '';
if (!cli || !existsSync(cli)) process.exit(0); // Speculate was uninstalled
try {
  const { speculateSync } = await import(`file://${cli.replace(/\\/g, '/')}`.replace(/cli\.js$/, 'sync.js'));
  await speculateSync({ self: { command: process.execPath, args: [cli] }, mode: null });
} catch {
  // Never block a session start.
}
process.exit(0);
```

Note the import target is `sync.js` next to `cli.js` in the same `dist/src`
directory; if that resolution proves awkward, spawn `node <cli> sync` with
`stdio: 'ignore'` instead and still exit 0 unconditionally. Either shape is
acceptable as long as a missing or broken CLI exits 0 with no output.
